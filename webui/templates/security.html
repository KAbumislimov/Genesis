Безопасность

Что реально защищает эту панель, простыми словами — и что ещё в планах

Вход в систему 2
Пароли не хранятся в открытом виде
У каждого пользователя свой аккаунт. Пароль хранится только как хеш с солью (Werkzeug/PBKDF2) — даже прямой доступ к базе данных не покажет ничей реальный пароль.
Учётные записи можно заблокировать и «выкинуть» из сессии
Блокировка пользователя (is_blocked) и принудительный выход (force_logout) применяются мгновенно — не остаётся «подвисшей» сессии, которая продолжает работать после отзыва доступа.
Роли и доступ 1
Каждый видит только то, что положено его роли
Admin, Staff и Viewer получают разный набор действий и разные разделы меню — управление машинами кампуса, настройками и пользователями доступно только роли Admin.
Сессии 1
Защищённая сессионная кука
Кука входа помечена HttpOnly (недоступна скриптам страницы), Secure (только по HTTPS) и SameSite=Lax (не отправляется при межсайтовых запросах).
Сеть и защита в браузере 3
Шифрование при передаче
Вся панель работает по HTTPS. Заголовок Strict-Transport-Security говорит браузеру больше никогда не откатываться на обычный HTTP для этого сайта.
Нельзя подгрузить чужой скрипт
Заголовок Content-Security-Policy блокирует загрузку кода с сайта злоумышленника — основная защита от атак вида «подмешать скрипт».
Нельзя встроить в чужую страницу
X-Frame-Options и соответствующее правило CSP не дают встроить панель в iframe на чужой странице — защита от «кликджекинга».
Секреты и резервные копии 2
Секреты хранятся не в коде
Пароли, ключи и токены задаются только в локальном файле конфигурации, который никогда не попадает в GitHub. Приложение теперь отказывается запускаться, если реальный секрет не задан — вместо того чтобы незаметно работать со значением по умолчанию, которое любой мог увидеть в исходном коде.
Ничего не живёт только на одной машине
Код автоматически бэкапится в приватный репозиторий каждый час; база данных и загруженные файлы бэкапятся отдельно по расписанию.
Что ещё в планах 2
Отдельные токены на форму (CSRF)
Сейчас подделку межсайтовых запросов блокирует настройка куки SameSite=Lax. Отдельный токен на каждую форму — следующий уровень защиты, запланирован, но пока не реализован.
Независимая проверка безопасности
Всё на этой странице — результат самопроверки вместе с ассистентом, который сопровождает эту панель. Логичный следующий шаг — внешний пентест для независимого подтверждения.
