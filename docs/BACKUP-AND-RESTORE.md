# Резервное копирование и восстановление: как это устроено

Цель: **если сервер сгорел или заменили железо, одна команда из GitHub возвращает всё** — код, пользователей,
роли и права, настройки, расписание, Helpdesk, службы и cron. Команда и порядок действий — в [RESTORE.md](../RESTORE.md).

## Цепочка (что и когда происходит само)

```
каждые 45 сек   github-live-sync.sh (держит watchdog, @reboot и */5 в cron)
                └─ scripts/backup-to-github.sh
                     1. scripts/export_state.py   → campus-infra/state/*   (права, настройки, машины, расписание,
                                                     crontab, systemd, зашифрованные снимки БД)
                     2. scripts/update_journal.py → campus-infra/docs/journal/ГГГГ-ММ-ДД.md   (что менялось)
                     3. git add campus-infra helpdesk-ops ops-journal → проверка «нет ли секрета в diff» → commit → push
                └─ при новом коммите — уведомление в Telegram со списком изменённых файлов

каждый час      cron: backup-to-github.sh (страховка, если live-sync остановился)
каждый день 03:00   cron: backup-data.sh — копии БД в ~/campus-backups (локально, 30 дней)
каждое воскр. 02:00 cron: campus-backup.sh — бэкап машин и музыки на Proxmox (10.20.1.106)
```

Если коммит не нужен (изменений нет), ничего не пишется. Если в diff нашёлся похожий на секрет текст — коммит **отменяется**
и в логе `~/log/campus-backup-to-github.log` появляется «СТОП: похоже на секрет».

## Что лежит в `campus-infra/state/`

| Файл | Содержимое | Читаемо? |
|---|---|---|
| `roles.json` | какие привилегии включены у каждой роли (галочки страницы «Роли и права») | да |
| `settings.json` | настройки панели (тема по умолчанию, режим тишины, Telegram-уведомления). PIN-хеши и всё, что похоже на секрет, **не выгружается** | да |
| `machines.json` | список кампусов/устройств (страница «Машины») | да |
| `users-summary.json` | логины, роли, блокировка (без паролей и личных данных) | да |
| `schedule.json`, `crontab.txt`, `systemd/`, `etc/chrony.conf` | расписание, cron сервера, службы, NTP | да |
| `webui.db.enc` (+`.meta.json`) | **полный снимок БД веб-панели**: gzip + AES-256, ключ `BACKUP_VAULT_PASS` | нет |
| `helpdesk_ops.db.enc`, `helpdesk_ops_uploads.tar.gz.enc` | Helpdesk Ops: тикеты и вложения (раз в сутки) | нет |

Снимок БД обновляется, когда изменились пользователи / права / настройки / машины (не чаще раза в 2 часа) и не реже раза в сутки.
Изменения состояния (кто кому что выдал, добавлена или удалена машина, заблокирован пользователь…) автоматически записываются
в журнал — раздел «Изменения состояния системы».

## Что НЕ в GitHub (и почему)

* **Media ~800 МБ** (звонки/гимн) — велика для GitHub. Копия — на Proxmox (`campus-backup.sh`, еженедельно), возврат: `scripts/restore-music.sh`.
* **Музыка «Kamran Music» ~33 ГБ** — **нигде не бэкапится** (ни GitHub, ни Proxmox). Единственная копия — диск сервера; нужна отдельная копия вручную.
* **Секреты** (`.env`, токены ботов, SSH-ключи) — в приватном `campus-secrets`. Там же живёт ключ, которым зашифрованы снимки.
* Аватары, голосовые сообщения чата, кэш моделей — второстепенное, остаётся локально (`data/webui/`).
* Вложения Helpdesk Ops больше 40 МБ — только локально (сейчас ~11 МБ, помещаются).

## Ручные проверки и операции

```bash
bash ~/projects/campus-infra/restore.sh --verify                  # проверка «восстановится ли» (ничего не меняет)
python3 ~/projects/campus-infra/scripts/export_state.py           # выгрузить состояние прямо сейчас
python3 ~/projects/campus-infra/scripts/import_state.py verify    # расшифровать снимки и проверить целостность
python3 ~/projects/campus-infra/scripts/import_state.py restore --force   # вернуть БД из снимка (старая сохранится рядом)
tail -f ~/log/campus-backup-to-github.log ~/log/github-live-sync.log      # что происходит сейчас
```

Восстановить только права ролей без замены БД: страница «Роли и права» → «Сбросить», либо
`python3 scripts/import_state.py json --db <путь к webui.db>` (накатит `roles.json`, `settings.json`, `machines.json`).

## Смена ключа шифрования

Ключ — `BACKUP_VAULT_PASS` в `campus-secrets/server/.env` (копия на сервере в `~/projects/campus-infra/.env`).
Сейчас он короткий; лучше заменить на длинный (20+ символов): поменять в обоих местах и запустить `export_state.py` —
через сутки (или после правки пользователей/прав) снимки перешифруются. Старые снимки в истории git остаются зашифрованными
прежним ключом — если ключ считается скомпрометированным, историю нужно чистить (`git filter-repo`).

## Рост репозитория

Снимки — бинарные файлы: webui ≈ 60 КБ, Helpdesk ≈ 0,5 МБ (раз в сутки), вложения ≈ 10 МБ (только при изменении). Ожидаемый
прирост — порядка сотен МБ в год. Если репозиторий раздуется, историю `state/` можно сжать (`git filter-repo --path campus-infra/state --invert-paths`
для старых коммитов) — актуальные снимки создаются заново автоматически.
