# Роли и привилегии

Что может делать пользователь, определяется **ролью** (`guest`, `user`, `staff`, `helpdesk`, `eventmanager`, `admin`) и
**привилегиями** (39 штук в 7 категориях), которые админ включает галочками на странице **«Роли и права»** (`/admin/roles`).

* Категории: Плеер и звук · Эфир на весь кампус · Автоматика и расписание · Музыкальная библиотека · Мониторинг и сервис ·
  Контент и оформление · Администрирование.
* Роль **admin** всегда имеет всё. Привилегии `users_manage` (пользователи) и `roles_manage` (эта страница) закреплены за admin и
  никому не выдаются (защита от повышения прав). «Опасные» права (терминал, удаление файлов, перезапуск служб…) подсвечены.
* Изменения вступают в силу сразу (кэш 5 секунд), каждое пишется в «Лог активности» (`role_perm`) и в `docs/journal/`.
* Стандартные значения повторяют прежнее поведение системы: `DEFAULT_ROLE_PERMS` в `app.py`. Кнопка «Сброс» у роли возвращает их.
* Личное право на гимн (галочка у пользователя на странице «Пользователи») по-прежнему открывает спецсигналы.

## Где хранится

Таблица `role_perms(role, perm, allowed)` в `webui.db`; копия в GitHub — `state/roles.json` (читаемо) и зашифрованный снимок БД.
После восстановления на новом железе права возвращаются вместе с БД.

## Как проверять право в коде

```python
@perm_required('terminal')            # страница/маршрут (отказ → редирект на главную)
if not has_perm('tracks_delete'):     # внутри функции; ответ на отказ — как раньше (JSON или 403)
    return jsonify({'ok': False, 'error': 'Нет прав'})
```
```jinja
{% if can('upload') %} … {% endif %}   {# в шаблонах #}
```

Старые имена `next`, `prev`, `vol`, `cron`, `admin` работают как алиасы (`_PERM_ALIASES`).

## Как добавить привилегию

1. Строка в `PERM_CATALOG` (ключ, название, описание), при необходимости — в `PERM_DANGER`.
2. Значения по умолчанию — в `DEFAULT_ROLE_PERMS`. Новая привилегия автоматически появится в БД при старте (`ensure_role_perms`), не затрагивая настроенные галочки.
3. `has_perm` / `@perm_required` в маршруте, `can()` в шаблоне.
4. Перевод названия и описания — `static/i18n-auto-roles.js`.

## Проверка после изменений

Скрипты сравнения «до/после» по всем ролям и маршрутам — `scripts/tests/perm_matrix.py`, `perm_feature_test.py` (см. `scripts/tests/README.md`;
принцип: копия БД, тестовые пользователи каждой роли, запросы с заведомо неверными аргументами, сравнение кодов ответов).

## Привилегия «Стартовая страница входа» (`login_style`, 2026-09-20)

Категория «Контент и оформление». Позволяет выбрать внешний вид страницы входа для всех (Настройки → «Стартовая страница входа»: 20 вариантов с превью, кнопка «Сделать стартовой»).
По умолчанию есть только у админа (админу выдана всегда); остальным роутам выдаётся галочкой на странице «Роли и права». API: `GET/POST /api/login-style` (403 без привилегии).

## Привилегия «Дизайн плеера по умолчанию» (`ui_default`, 2026-09-20)

Категория «Контент и оформление». Позволяет в Настройках → «Дизайн интерфейса» нажать «Сделать основным для всех»: этот дизайн увидят все, кто не выбрал свой.
Личный выбор пользователя всегда сильнее. У админа есть всегда, остальным выдаётся галочкой на странице «Роли и права». API: `GET/POST /api/ui-default` (403 без привилегии, 400 на неизвестный ключ).
Проверка: `scripts/tests/ui_default_perm_check.py`.
